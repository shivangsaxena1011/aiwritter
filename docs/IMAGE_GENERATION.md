# AIWritter — Academic Diagrams & Image Generation

Textbook diagrams must convey technical precision rather than decorative artistic flair. AIWritter enforces strict academic standards for technical figures, architectural schematics, and scientific plots.

---

## 1. Aesthetic Guidelines: Monochrome & Technical Line Art

AIWritter enforces three strict rules for all textbook visuals:

1. **Monochrome Palette:**
   - Background: Pure solid white (`#FFFFFF`).
   - Foregrounds: Black (`#000000`), dark charcoal (`#1E293B`), and neutral grey tones (`#64748B`).
   - Banned: Vivid neon colors, textured artistic gradients, dark backgrounds.
2. **Technical Clarity:**
   - Clear vector-style line art, labeled dimensions, flow arrows, and annotated components.
   - Clean axes, gridlines, and labeled physical quantities.
3. **No Decorative Tropes:**
   - Prohibited: Photorealistic people, whimsical cartoons, 3D claymation, abstract decorative stock art.

---

## 2. Diagram Modalities & Provider Selection

When `DiagramPlannerAgent` identifies a section requiring visualization, it selects one of two modalities:

### Modality A: Deterministic Scientific Charts (Matplotlib)
Used for continuous functional responses, thermodynamic curves, frequency responses, and empirical benchmarks:
- Clean 300 DPI vector-like export.
- Universal `DejaVu Sans` font ensuring cross-platform rendering consistency without OS-specific font dependency.
- Uncluttered legends, muted gridlines, and precise mathematical curve formulas.

### Modality B: AI-Generated Schematics (Google Imagen 3 / Gemini)
Used for physical system cutaways, circuit block diagrams, cell structures, and molecular geometries:
- Prompt generated by `DiagramPromptAgent.create_textbook_diagram_prompt()` enforcing line art, white backgrounds, and technical annotations.
- Model: `imagen-3.0-generate-002` (configurable via `GEMINI_IMAGE_MODEL`).

---

## 3. Resilient Fallback Architecture

Visual asset production never blocks or fails a textbook build. The `DefaultImageProvider` (`backend/app/services/image/image_provider.py`) implements a 3-tier fallback hierarchy:

```
[Diagram Request]
       │
       ▼
Attempt 1: AI Image Generation (Google Imagen 3)
       │
       ├─► Success: Validate Image (Bytes, Dimensions, Format) ──► Embed in DOCX
       │
       └─► Failure (API Quota, Network, Blocked Prompt)
                 │
                 ▼
Attempt 2: Deterministic Scientific Plot (Matplotlib)
       │
       ├─► Success: High-Res Plot Generated ─────────────────────► Embed in DOCX
       │
       └─► Failure
                 │
                 ▼
Attempt 3: Formatted Academic Callout Box
  - Formatted text box in Markdown with Figure Caption,
    Technical Description, and Visual Specifications.
```

---

## 4. Image Validation Engine

Every generated image is validated by `DefaultImageProvider.validate_image()` before document embedding:
- **Magic Byte Verification:** Inspects binary headers to confirm valid PNG (`\x89PNG\r\n\x1a\n`), JPEG (`\xff\xd8\xff`), or WebP (`RIFF...WEBP`).
- **File Size Threshold:** Rejects truncated or corrupted files under 500 bytes.
- **Pillow Verification:** Parses image dimensions and color mode using PIL to prevent Word XML corruption.

---

## 5. Chapter-Aware Figure Numbering

All figures adhere to academic press numbering conventions:
$$\text{Figure } \langle\text{Chapter Number}\rangle.\langle\text{Figure Number in Chapter}\rangle \text{ — } \langle\text{Descriptive Caption}\rangle$$

Examples:
- `Figure 1.1 — Schematic Illustration of Infinite Potential Well Boundary Conditions`
- `Figure 1.2 — Empirical Polarization and Efficiency Curve for Polymer Electrolyte Cells`
- `Figure 2.1 — Kronig-Penney Periodic Potential Model in Crystalline Lattices`
